## What Went Well

**Alice (Product Owner):** Epic 5 closes the multi-channel loop. Reps search contacts, dial, log outcomes, promote interested calls into the same pipeline as D2D, and admins see call counts in the daily summary grid. FR24–FR31 are covered end-to-end.

**Charlie (Senior Dev):** Story sequencing mirrored Epic 2’s knock flow deliberately — schema (5.1) → panel + search (5.2) → log RPC (5.3) → promote (5.4) → history (5.5) → metrics (5.6) → UX polish (5.7). Each story had a narrow surface area.

**Amelia (Developer):** The calls vertical slice is coherent:
- `src/features/calls/*` — server reads/writes, hooks, RPC wrappers
- `src/components/calls/*` — panel shell, form, history, script, dial link
- `src/app/api/v1/calls/*` + `contacts/[id]/calls` — rep-scoped REST
- `fetch` + hooks (`useContactSearch`, `useContactCallHistory`, `useRepDailyCallCount`, `useCallScript`) — no TanStack Query, consistent with Epics 3–4

**Dana (QA):** `create_call_log` SECURITY DEFINER solved cross-rep contact logging cleanly. Sydney day bounds (`startOfDaySydney` / `endOfDaySydney`) reused from knocks — one calendar semantics source. Code reviews caught real UX bugs in `calls-panel-shell.tsx` (form state on contact switch, promote placement, stale history, nested tel link).

**Winston (Architect):** RLS + RPC split held: reps read/write own call rows; admins read all; promote and search use invoker/definer appropriately. `call_script` singleton with seed + admin UPDATE policy sets up Story 7.8 without shipping admin UI early.

## Key Lessons Learned

1. **Mirror proven epic patterns for new channels.** Call logging copied knock promotion (`promote_call_to_lead` ↔ `create_knock_with_contact`), contact search RPC, and pipeline `source=call` — minimal design risk.

2. **Plan SECURITY DEFINER RPCs in the story before the panel ships.** 5.2 dev notes correctly deferred cross-rep insert to 5.3’s `create_call_log` — avoided premature RLS patches.

3. **`refreshKey` unifies dependent UI.** Single bump after log refreshes call history and daily counter — extend this pattern when adding new post-log surfaces.

4. **Shell components need contact-switch checklist.** Remount forms with `key={contactId}`, clear session promote state, fix hook stale data — recurring review findings share one root cause.

5. **Defer admin configuration to named later stories.** `call_script` table in 5.7, editor in 7.8 — reps get value immediately via seed; no scope creep.

6. **Invalid HTML from incremental UX wrapping.** Adding `PhoneDialLink` inside existing row `<button>` broke nesting rules — check interactive element tree when wrapping tap targets.

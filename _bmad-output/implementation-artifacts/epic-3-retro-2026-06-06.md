## What Went Well

**Alice (Product Owner):** Epic 3 gives managers a coherent picture — map, feed, daily grid, coaching flags, and routes. Each story built on the last without rework.

**Charlie (Senior Dev):** We locked in a repeatable admin stack early:
- `GET /api/v1/admin/*` + `requireRoleForApi(["admin"])`
- `src/features/admin/*` for server queries and client hooks
- `fetch` + `loadedKey` hooks (no TanStack Query)
- Supabase RPCs for aggregated reads, applied via MCP migrations

**Amelia (Developer):** Story 3.1 set the map shell/canvas split and filter semantics. Stories 3.2–3.5 extended that foundation instead of reinventing it. Realtime in 3.2 and the low-activity refetch trigger in 3.4 show good cross-story integration.

**Dana (QA):** Every story passed `npm run lint` and `npm run build`. Code reviews caught real bugs (Realtime races, shift-scoped knock logic, stale polylines) before they became production issues.

**Winston (Architect):** Sydney timezone handling via `format-knock-date.ts` became the single source of truth for 3.3, 3.4, and 3.5 — no duplicate date math.

## Challenges and Growth Areas

**Charlie (Senior Dev):** The `loadedKey` hook pattern appeared in every story, and we kept hitting the same edge cases: error paths not updating `loadedKey`, stale data visible during refetch, and stale map/route data after rep/date changes.

**Elena (Junior Dev):** Realtime + REST concurrency in 3.2 was tricky. The initial load could overwrite Realtime prepends — we only caught it in review.

**Alice (Product Owner):** Morning overview shows `calls: 0` until Epic 5 — that's expected per spec, but stakeholders may ask. We should set expectations before demoing the dashboard.

**Dana (QA):** Manual testing only — no Playwright for admin flows. Acceptable for v1, but Epic 4's drag-and-drop pipeline will need more automated coverage eventually.

## Key Lessons Learned

1. **Establish patterns in Story 1 of an epic.** Admin map shell (3.1) paid off in 3.5 — breadcrumb layers dropped in without restructuring the page.

2. **Code review is finding systemic hook bugs.** Error-path `loadedKey` and stale-data-on-rep-change appeared in 3.3 and 3.5. Future hooks should use the 3.5 pattern: clear data on error, derive empty `points` while `loading`.

3. **Realtime needs explicit merge semantics.** REST initial load + Realtime subscription must dedupe and not clobber — document this in story specs for any future Realtime feature.

4. **Shift boundaries ≠ calendar day boundaries.** GPS breadcrumbs (3.5) and low-activity flags (3.4) both depend on shift scope — keep shift resolution logic consistent and centralized.

5. **Defer consciously, log consistently.** `deferred-work.md` now tracks Epic 3 items; prevents re-litigating the same decisions in Epic 4+.

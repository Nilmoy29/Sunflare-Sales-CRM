## Key Lessons Learned

1. **Global date range must land first in analytics epics.** 7.1's context provider prevented eight separate date-picker implementations and made Realtime gating (`isToday`) consistent across coaching widgets and summary refetch (7.7).

2. **Reuse summary RPC before writing new SQL.** Leaderboard ranking, shift-end totals, and deep-dive period totals all derive from `get_admin_daily_rep_summary` — one metric definition source of truth.

3. **Post-commit response validation is a footgun.** Mutations that `parse()` after DB success can 500 while state is committed — use `safeParse` + fallback payload (7.7, 7.8). Add to dev-story checklist.

4. **Client-side CSV is sufficient for admin-only v1.** 7.6 avoided server export routes; in-memory hook data + RFC 4180 escaping + BOM satisfies FR50 with zero new API surface.

5. **Split rep vs admin API routes for shared config tables.** 7.8 kept rep `GET /api/v1/calls/script` rep-only; admin GET/PATCH on separate paths — clean NFR10 story from 5.7 deferral.

6. **Story "do NOT" lists kept Epic 7 tight.** No TanStack Query, no chart libraries, no Realtime on analytics widgets, no shift-window aggregation in v1 — reviews stayed focused.
